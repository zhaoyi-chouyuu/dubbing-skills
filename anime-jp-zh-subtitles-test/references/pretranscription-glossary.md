# 听写前人名与专有名词清单

每次开始音频听写之前执行。先保存 `glossary.json` 和便于阅读的 `人名与专有名词清单.txt`，再启动 ASR；清单放在本次运行目录，交付时随 QC 保存到素材目录。可以复用同一项目的既有清单，但本次须核对来源版本、补入新增集数并保存快照。条目尚有缺项时如实记录，不因此暂停整集制作。

## 来源与核对

1. 确认作品、季数、集数及素材版本。读取本次范围的原日语字幕，提取人名、别名/昵称、地名、组织、技能、道具及作品专属用词。保留原字形、字幕 ID 和原时间；不要将 ASR 输出或 Agent 自行整理的旧表误当原字幕。
2. 查看 OP/ED 的角色/演职员等画面文字，交叉核对角色字形；保存视频路径、时间点及可定位的截图证据。区分角色名、声优名与工作人员名，不能把署名当角色，也不因画面出现文字就认定它是剧中术语。没有这类画面、字太小或无法辨认时记录缺证，不编造来源。
3. 用户已有项目清单时先读取，明确指定的项目写法优先；同时记录它与原日语字幕、OP/ED 的差异。通常以原字幕中的专名写法建立本次基准，OP/ED 用于交叉验证和补缺。两者冲突时核实是否同一实体、别名或版本差异；只有明确文字证据才调整选定写法，并保存理由。证据不足则保留该句原字幕写法、列出冲突，不按频次或 ASR 多数票决定。
4. 只有日语 PDF 台本时，记录 `reference_kind=ja_script_pdf`，以角色表、对应对白及明确的手写修订作为文字来源；疑似提取错字回看原页，区分对白、角色标签、音效和舞台提示。PDF 没有可信字幕时间码，不能称作已经对齐的日语字幕。原字幕与台本同时存在时，优先使用与成片对应的原字幕，台本辅助核名并记录差异。
5. 只有英语字幕或没有原日语字幕时，仍建立清单，使用可辨的 OP/ED 画面、用户清单或日语台本；缺项才补查官方来源。来源不可得时记录待定，不用英语反译或模型常识猜定日文字形。

OP/ED 在本清单步骤提供专名文字证据；另按 [画面文字规范](subtitle-format.md#画面文字片头片尾与广告)，将 OP 的作品名、原作出处、出品方/版权信息和每话话数/标题写入交付 SRT，不把“专名取证”和“画面字交付”混为一项。歌曲继续默认排除在听写、歌词检查和交付字幕之外；如片头片尾含正片对白，按实际场景区分，不把对白一并丢掉。同版重复 OP/ED 可复用已经查看的画面证据，记录对应版本，不必逐集重复全段检查。

## 保存内容与使用边界

每条至少保存：实体 ID、类别、选定写法/待定状态、各来源原写法、别名与实际称呼、读音（未知可空）、作品/集数、源文件路径及哈希、源字幕 ID/时间或 PDF 页码或画面时间、证据、冲突与选择理由。记录本次清单版本及 ASR 开始前已保存的状态；同时标明文字来源确认与声音读法确认，不能混为一个 confirmed。

原字幕不是绝对真值，但它的人名和专有名词是本项目必须对照的文字依据。已确认同一实体的字形差异可以统一；保留对白实际使用的姓/名、昵称、敬称及别名，不强行展开成全名，不把虚构词改成现实常用词。没有身份/发音依据，不可仅因词表有某个名字就填入台词。

这份清单可指导 Agent 后续审查，不把原字幕全文、猜测台词或答案提示灌入首轮 ASR。继续遵守主技能的独立识别和 Anime Whisper 无提示规则。清单中能回到原字幕/实际画面的已核实条目可用于字形核对，不要求用户逐项确认；缺证的 Agent 猜测条目只作候选。

听写完成后逐项对照原字幕及清单，记录涉及输出 ID、异写修改与未解决冲突，再执行全文逻辑校对；最终 SRT 修订后同步更新清单和 QC 的输出 ID。
