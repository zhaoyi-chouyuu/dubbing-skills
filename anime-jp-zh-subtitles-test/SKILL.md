# 日语动画字幕生成与复核

> **TEST / 实验版 v0.16，持续迭代中。** 本流程尚未完成当前默认单模型流程的完整视频端到端验收，也未验证数千分钟批处理的稳定性；后续根据实际素材继续修订。

流程 v0.17（Windows／WSL 适配）。默认交付日语 SRT 与独立 QC。英语参考用于引导日语听写；已有日语字幕时逐块音频校对，听不清就保留原文并记 QC。两种情况默认均使用 Anime Whisper 单模型听写/核查，并完成全音轨查漏及全文校对。只有用户或本次项目明确要求双模型时才追加第二个 ASR。文字和语义断句确认后，默认对完整授权范围的全部对白执行既有 V26 流程，逐条重新确定入点、出点和交接；画面字按实际视频帧核时。仅用户明确要求保留原时间码时使用保留分支。Anime Whisper 不决定断句或 timing；声纹默认关闭，中文翻译按需。

这是供 Agent 执行的工作流技能，不是已打包的 ASR 引擎或一键程序。执行时核实实际模型、依赖与接口；不得将技能结构验证报告为音视频试跑成功。

## 范围与运行条件

- 本机用户偏好：优先在 WSL2 Ubuntu 的 Linux 原生环境执行 ASR、音频处理和精对齐；Python、模型及计算缓存优先使用 `/home/zhaoyi/...`。Windows 可用于文件管理和结构检查，不因短测速略快而自动切换正式计算后端。WSL 不可用或关键依赖缺失时，先记录具体阻碍，再评估 Windows 后备路径；不要静默切换。稳定性优劣仍需持续运行证据，不能将此偏好报告为已验证的稳定性结论。
- 效率也是交付要求：默认保留 Anime Whisper 单模型主稿/核查、完整授权范围的 V26 全量时间对齐、全音轨查漏和最终全文校对；全量首轮完成后的疑点与后续改字优先局部回听/重算，复用已加载模型与缓存。不能用仅改报警条、抽样复查或沿用旧轴替代全量首轮。声纹建库/聚类/角色比对默认跳过，不为未经验证的边际收益自动增加全片声纹集成或反复全片重跑。用户给出时限时按实际阶段耗时安排处理，扩展步骤须有明确问题和收益依据；不把短样本测速当整片含复核的总耗时，也不为赶时间把未完成的检查标成通过。
- 仅要求创建、修改或评估技能时，不启动视频听写。明确要求试跑后，完成授权范围内的听写、复核、翻译与输出，不逐步重复询问。
- 默认源语言和字幕语言均为日语。交付 UTF-8 日语 SRT，默认放在源视频同目录，命名 `<视频名>.ja.srt`；已有同名成品时保留旧版本并写明新版本路径。ASR 原始 JSON、音频片段和 QC 报告是内部处理/追溯材料，不替代用户需要的字幕成品。用户指定其他位置、格式或语言时遵从指定；不默认增加中文翻译。
- 用户明确要求给视频做字幕且未限定范围时，处理所给视频的完整正片范围，默认排除已确认 OP/ED 的音频听写与歌词，但 OP 的作品名、原作出处、出品方/版权信息及每话话数/标题等指定画面字必须加入 SRT，详见 [画面文字规范](references/subtitle-format.md#画面文字片头片尾与广告)；长视频分块落盘并支持恢复，不因旧技能名含 test 而只交付前 10 分钟。明确要求小范围实验时才按指定范围试跑；未指定实验片段时可选总计不超过 10 分钟的代表性片段并写明原片范围。不得从一个视频扩展到未指定的整个目录或其他素材。
- 原视频、原有字幕和正式技能保持可追溯。每次新建运行目录；先读 [运行记录与验收](references/run-records.md)，建立媒体、时间映射、模型与阶段记录。
- 提取音频时保留原视频时间映射，处理音轨偏移、重采样及非连续测试片段。裁剪片段的 0 秒不能误当原片 0 秒。
- 默认 `asr_mode=single`、`asr_primary=anime_whisper`：使用 `litagin/anime-whisper`（本机 `/home/zhaoyi/models/anime-whisper`，revision `22e2008a8182b357da3922a6308d095008f72973`）完成完整范围听写或参考字幕核查。除非本次明确要求，否则不加载、运行或下载 Turbo 等第二个 ASR；质量疑点本身不自动启用双模型。
- 用户明确指定其他单模型时，仅使用指定模型，记录覆盖默认值的指示。明确要求双模型时才设置 `asr_mode=dual`，记录授权、主次角色和范围；未另指定时 Anime Whisper 为主，Turbo 为独立复核。两者同属 Whisper 系，不能称为不同模型体系或统计独立验证。
- Anime Whisper 现在承担主稿听写，不再仅作文本审查。其标点、长句、生成窗口和时间输出仍不能直接决定字幕断句或最终 timing；窗口只用于查找原音，V26 决定精确边界。
- 仅预检本次选用的 ASR。Anime Whisper 检查配置、处理器及真实 `model.safetensors`；只加载处理器不算加载成功。只有选用 Turbo 时才检查其 `model.bin`、配置和分词器。默认单模型模式中，未启用的第二模型标 `skipped_by_config`，缺少其权重或依赖不阻塞；选中模型缺失则记 `blocked_dependency`，不静默换型号。记录实际仓库、revision、运行库、GPU/精度与可读性，模型和缓存优先放非同步本地目录。

先读 [本机环境与依赖](references/local-runtime.md)，可运行 `scripts/preflight.py` 做无媒体、无网络的文件和包元数据检查；该检查不加载模型，不证明 CUDA 推理可用。实际试跑前仍需记录本次选用模型的真实权重加载、设备和接口检查。Qwen3-ASR 缺失不阻塞默认单模型流程；仅修改技能不启动下载或媒体处理。

## 参考字幕分支与项目人名清单（优先规则）

有同版英语或日语参考字幕时，先读 [参考字幕引导听写与校对](references/reference-subtitle-review.md)。两种情况共用 WSL、默认 Anime Whisper 单模型听写/核查、全音轨查漏、项目人名核对、格式检查和最终全文校对；只改变参考字幕的用途及疑句保留策略：

- `reference_language=en`：按英语字幕块听写日语。英语辅助理解和查漏；结合发音、英语和上下文选最有依据的候选，推断依据及未确认部分写 QC，不把纯反译当作已听清的日语。
- `reference_language=ja`：以现有日语字幕为底稿，逐块比较独立 ASR、声音和原字幕。明确听清且能确认原文有误才改字、补漏或删重复；听不清、证据不足或模型冲突时保留原字幕措辞，在 QC 记录原文、候选、时间及理由，不以 ASR 多数票或英语反译替换。原文保留不等于已核实；已有 QC 的推断和未解决状态必须继承，取得新证据后才能关闭疑点。

参考语言和 timing 分开记录。默认 `timing_mode=v26`：文字校对、补漏和语义/人物断句完成后，对用户授权范围内全部应交付对白重新对齐；原字幕时间仅作查找上下文的粗定位，不作为最终边界或不可越出的窄时间框。参考字幕来自日语、英语、客户示例，或旧稿曾被认为时间可信，都不自动跳过此步骤。用户/客户反馈 timing 不准、未与声音同进同出或要求全量返工时，该返修范围必须全量重对齐，不得仅处理样例集、少量疑点或统一平移。授权整集则覆盖该集完整处理范围，授权整季则逐集完成，明确限定片段时只覆盖该片段；默认仍排除已确认 OP/ED 音频与歌词。只有用户明确要求“只改文字/保留原时间码”时才使用 `timing_mode=trusted_reference`，记录该指示及时间来源；这一例外不能自动用于 timing 返修。

英语和日语字幕同时存在时，日语作校对底稿，英语辅助理解/查漏；允许跨块匹配，不强求两种语言 ID 一一对应。旧时间帮助找回原音，最终对白 timing 默认由全量 V26 决定。超长字幕先按自然语义换行，仍超出普通对白每行14字/通常每条28字或显示过长时按语义、原音停顿与交接拆条，保留源/输出的一对多映射，不按字数平均分时。全量首轮结束后再改字、补漏或改断句时，重对齐受影响范围与相邻接缝即可，不要求每次小改都重跑整集。

除已确认排除的 OP/ED 音频/歌词范围外，逐块记录处理结果并检查字幕框外的原音，不能静默漏台词。SRT 正文只放日语台词及规定的画面文字，不放「聞き取り要確認」「听不清」「待核」等审校占位或置信标签。疑点只写独立 QC，继续完成其余片段并交付 SRT 和 QC，不逐块等待用户确认；未解决项保持 `needs_review`，不宣称已全部核实。无参考字幕时使用默认 Anime Whisper 单模型听写，再执行 V26。

每次听写前，读取 [听写前人名与专有名词清单](references/pretranscription-glossary.md)，先从原日语字幕、OP/ED 画面文字建立并保存本次清单，再开始 ASR。已有用户项目清单一并核对；只有 PDF 台本时，用角色表、对白及明确修订作文字参考并记录来源类型。每次运行均保存来源版本和可读清单；跨集可复用已核实条目，新增/冲突条目继续补齐，不能仅在听写后临时整理。原日语字幕是高可信底稿，非 100% 正确的真值；人名和专有名词必须逐项对照原字幕及清单，不能被 ASR 常见词或剧情推测覆盖。具体冲突与缺项规则见该参考。

## 默认 Anime Whisper 单模型听写

使用 Transformers 的 `AutoProcessor`、`WhisperForConditionalGeneration` 真实加载本地 Anime Whisper 权重，优先 WSL / NVIDIA GPU。模型一次加载后复用，处理完整授权正片范围。首轮不灌入原日语台词、英语反译、前文答案或猜测词表；保留未经答案提示的原始输出，再与参考字幕、项目专名清单和原音比较。已有日语底稿不得被模型自动覆盖。

显式指定日语听写，记录生成参数、token 数和上限。可从20–30秒窗口、1–2秒重叠起步，按模型限制与场景调整；按时间和文字联合去重，保留真实重复对白，核查首尾和接缝。窗口位置是原音粗定位；无可靠词/字符时间时标 `chunk_only`，不伪造句内时间。

该模型常省略句末「。」；标点和生成块不能直接决定字幕断句。乱码、循环、触及生成上限、疑似截断及与声音不符的文本进入疑点表；同一模型偏移切窗复核不算独立模型验证，不能用多次一致代替声音核对。重复抑制试验另存结果，不覆盖首轮。

默认直接覆盖正片原音，不用 VAD 硬裁掉阴性区间。疑难段先扩大/移动切窗，必要时局部分离人声并与原音对照，再用同一个已选模型复核。没有额外指示时不调用另一 ASR 或有音频输入的生成模型作第二路听写；仍不清楚时保留原日语底稿并记 QC。

仅在 `timing_mode=v26` 时，确认后的主稿依据语义、原音停顿和实际交接自主断句，再全量 V26 对齐。不得将识别窗口直接当字幕块，或按字数硬切、平均分时；参见 [对齐适配约束](references/alignment-adapter.md)。

### 双模型仅在明确要求时启用

只有用户或本次项目明确要求双模型/第二模型复核时，才追加选定的第二路。通常使用本地 `mobiuslabsgmbh/faster-whisper-large-v3-turbo` 的 CTranslate2 副本；按 [本机接口](references/local-runtime.md) 执行。两路独立首轮不互读答案，尽量使用不同切片边界，保存各自原始输出，并按原音窗口进行一对多/多对一内容比较。未指定主次时 Anime Whisper 为主、Turbo 为辅助；显式指定以 Turbo 为主时遵从本次指示。两路一致或多数票不能代替声音证据；该分支的额外依赖只约束已启用范围。

## 全音轨查漏与联合复核

检查对象包含正片范围的全部音频时间和字幕内部，不只遍历已有字幕行；已确认排除的 OP/ED 不纳入音频听写和歌词校对；画面审查单独进行：OP 指定的作品/原作/出品方与版权/每话标题信息必须写入 SRT，其余画面文字按清单流程核对专名。不能用 OP 排除范围过滤掉应交付的画面字。

1. 独立 VAD 扫描正片范围的音轨，必要时比较原音与辅助人声检测。VAD、能量和音频事件分类只是候选证据，不能单独证明有/无对白。
2. 对比 ASR 及字/词对齐覆盖，寻找未解释的说话区间。长字幕框覆盖整段声音不能证明里面的词齐全，不能只用字幕框并集衡量覆盖。
3. 默认将 Anime Whisper 原音窗口、参考字幕与实际声音逐段匹配；只有已启用双模型时才额外匹配两路片段，允许一对多、多对一。候选字级对齐未通过声音/粗边界检查时，不得据其派生精确缺字位置；整窗高相似度也不能清除短句、否定或姓名差异，保留编辑片段。汉字/假名、标点、分句差异可仅为比较做规范化，原始文本保留。否定、数字、人名、主体和短应答差异不能因大意相近而忽略。
4. 建立疑点：少句/少词、ASR 与参考/原音不符（双模型启用时另记两路分歧）、边界吞句、异常重复、语音无字、文字无声音、字音不匹配、异常语速、重叠对白。短声音可能是「え」「うん」，不能统一过滤。
5. ASR 空白且 VAD 阴性的区间（双模型时含共同空白）也保留记录，用偏移切窗复扫或独立音频事件检测扩大检查，不能据模型空白宣称绝无对白。抽查只是附加检查，不算全量查漏。

对疑点提取带前后文的原音频。先扩大/移动切窗重听，再按问题选辅助人声或同一模型偏移窗口复核。仅明确要求第二模型时才使用另一 ASR/音频生成模型；第二路先独立听写再看候选，减少答案诱导。

依据声音、候选差异和对齐证据，同时决定补句、改字或改时，保存理由及来源。两票对一票不是充分依据。检测词表提示被直接复读、异常循环和模板化输出，将它们作为待查候选；未经声音支持的新候选不得替换字幕。日语分支听不清时保留底稿是待核保留，不是声音验证通过；不得据此删除原文或替换为猜测。不能把增益处理或更大模型默认当作更正确。纯文字 Agent 不能声称听过音频，也不能按剧情补台词。

每个疑点默认最多 3 轮追加复核，记录方法与结果，避免原样无限重试。仍不能判断时记 `unresolved`，保留片段与候选，继续其他片段；不得悄悄删句、无依据猜写或判通过；英语引导模式允许采用声音与英语共同支持的最佳候选，但必须在 QC 保留推断状态；日语校对分支仍保留原字幕，不用此推断覆盖底稿。关键依赖/服务整体失效时停止受影响阶段。

每次修改后重查相邻边界、覆盖与证据。可只重算受影响范围及上下文；缓存键须含音频、模型/参数、文本版本。日语修订后使相关中文译文失效并重译。

## 角色声纹辅助交接边界（可选，默认关闭）

当前只生成日语 SRT 时跳过本阶段，不检查/加载声纹模型、不建角色库、不做匿名声纹聚类，也不默认执行 CAM++／ECAPA512／ResNet34 集成。断句参考语义、原音停顿及能确认的对话交接，timing 默认由完整授权范围的 V26 全量对齐确定；仅用户明确保留轴时例外。听出换人或保留重叠对白不要求先知道角色身份。声纹资源缺失、未建库或本阶段跳过不阻塞字幕，也不能单独导致 needs_review。

仅当用户另行要求角色标注/身份一致性，或明确启用声纹实验时，读取 [声纹与说话人交接点](references/voice-boundaries.md)。优先复用现有可靠库，针对确有身份判别需要的片段采用最小可行方案；先记录实际耗时与解决的问题，再决定是否扩大。声纹只能辅助身份/边界证据，不能替代字词对齐、解决重叠语音分离或单独确定精确字幕切点；不得从普通字幕请求自动恢复本阶段。

## 极短夹带残留检查

文字确认后、对齐前，以及最终合并成品后各运行一次 [极短夹带检查](references/short-transition-review.md)。检查 `A → A/B → B`、块内重复与接缝残留；800ms 仅是默认筛选阈值，不是删除依据。保留真实重复、双人叠说、独立短应答与画面字。纯对齐只报告；有文字返修授权时，按参考字幕/台本的序号与前后相对位置复核，不能按参考时间码硬匹配。无法确定的保留原段并列 QC。

## 复用现有精对齐

默认在文字和断句确认后，对完整授权范围的全部对白执行本阶段；已有字幕、旧轴曾获确认或自动 QC 未报警均不构成跳过理由。只有用户明确要求保留原时间码时才走 `trusted_reference` 分支。先读取已安装的 `subtitle-align-skill-gpu` 及其 DeepSeek V26 同步入口，执行环境预检、引擎哈希锁校验、原稿体检和极短夹带扫描；按其 V26 主引擎执行结构预处理、分段精对齐、VAD 辅助边界检查及逐集 QC，再遵守 [本机环境与依赖](references/local-runtime.md) 和 [对齐适配约束](references/alignment-adapter.md)。本机可复用实现在 `/mnt/c/Users/zhao-/.dsh/skills/subtitle-align-skill-gpu/master_aligner_v26.py`，单文件接口为 `align_one(audio_path, srt_path, output_path, vad_mode="hybrid")`；执行前核对实际源码与签名，不能把技能中的旧示例代码等同于当前引擎。

最终对白 timing 使用既有 `subtitle-align-skill-gpu` 的 V26 方法。每个应交付发话单位都进入全量首轮，保存新起止、字符映射、匹配/失败/回退状态；不因文字未改、旧轴看似可用或没有报警就跳过。实际核查过的原音窗口提供粗定位（默认来自 Anime Whisper 输入窗口），V26 字符对齐确定句内起止，再映射回确认的字幕块。Anime Whisper 不提供时间锚点、不对边界投票。画面字不送入音频对齐器，必须逐项按当前视频实际出现、消失与切镜核时；最后合并画面字、单人及双人对白并复查全部组合边界。

纯打轴请求可直接使用已安装的 `subtitle-align-skill-gpu`；动画生成/校对则先完成文本与断句，再复用其 V26 全量对齐。本流程中的归一化、匹配元数据、全音轨覆盖复核和重叠对白保护仍须核实或适配；不能盲用“静音/识别为空就压短”、按字数拉伸或统一延迟等启发式替代声音边界核对。全量重对齐不等于全片统一平移，也不保证每条数值一定变化。

读取对齐模型的预处理配置。本机日语 wav2vec2 配置为 `do_normalize=true`；使用现有底层接口时须在适配器中正确进行零均值/单位方差归一化。不要假定 `whisperx.align` 已调用特征提取器。归一化和高匹配分仍不能证明文字正确。

初始句内时间只是分句估计时，可将连续对白合并回有粗定位的短语音块联合对齐，再按字符映射拆回字幕。记录外层时间保护和内部拆句策略，避免将估计分句边界误当真值；不能仅为提高通过数而放宽阈值。

适配时保留以下约束：

- 现有接口输入可信日语 SRT，全局按所给文字顺序对齐。确认片段可以单独传入，正确换算片段/全片时间；不能假定已有增量接口。
- 单文件入口只调用 `align_one`，不会自动做完整行级 QC。另行保存行级 QC；V26 的字符对齐模型与 VAD 不属于第二路 ASR，但若附带 QC/DTW 会另载 Whisper/Turbo/medium 等 ASR 权重，必须有本次明确的第二模型指示，默认不启用。行级 QC 不替代全音轨查漏。
- 保存匹配状态、回退标记和对齐元数据；`fill_unmatched_timings` 等估计不是匹配成功，成功写出 SRT 不代表验收通过。
- 不盲用现有 `auto_fix` 中“识别为空就缩到 0.5 秒”等启发式修复。空白可能是漏听，应返回联合复核。
- 中文不能送入日语对齐模型。文字对不上声音时检查听写，不靠拉长字幕框或挪到别处掩盖问题。
- 短音过滤、裁尾及消重叠主要面向对白；遵守格式指南的重轴规则：对白与对白、画面字与画面字不重轴，画面字与对白可重轴且上画面字下对白。同一帧可辨的两人说话时合入同一字幕块、每人一行并在行首加 `- `；单人不加，众人齐声且不可辨个人时不用双人格式。真实重叠对白仍须保留双方；无法同时满足行长与准确 timing 时记录限制，不能机械截短/删除。

## 日语字幕成品、可选翻译与歌曲

日语 SRT 是默认主交付物。先读 [动画字幕格式与翻译要求](references/subtitle-format.md)（以用户本次提供的新版 DOCX 为准），并将其用于日语字幕排版、日语翻译和画面文字翻译。逐条复查行数/字数、显示时长、CPS、字幕间隔、标点、空格、断句、重轴、术语和屏幕文字；格式限制不能作为删台词或改写已听清原文的理由。难以同时满足语义、音频 timing 与规格时，保留内容和声音依据，记录超限及原因，不强行压缩或误时。普通对白单条最多两行、每行不超过14字符（含标点与空格），通常总计不超过28；大幅画面字可3–4行，日文画面字翻译允许保留大意，原则上满足字符/CPS要求，极限情况可记录具体例外，不将画面字例外用于删改听录对白。同轴时画面字在上、对白在下；双人对白用 `- `，众人齐声且无法分辨个人时不强套双人格式。单条时长通常0.8–7秒、字幕之间至少间隔一帧，CPS≤12且以5–7为宜。断句按自然短语与说话交接，避免拆碎词组、连续极短字幕或把识别窗口塞成一条。可信参考字幕也必须完成换行与必要的长段拆分，不得只扫描超限后原样交付；先修复能修复的格式问题，声音与规范确实冲突时才将具体例外记入 QC。确保序号、UTF-8编码、正时长、媒体范围和播放器可解析；文件结构合格仍不能代替内容与时间复核。

仅当用户要求中文时，日语片段确认且有稳定 ID 后翻译，保留日中映射。按中文阅读合并/拆分时保留所有源片段及声音范围；检查漏译、否定、人物关系、数字、人名和语气。不能把声音不确定的日语润色成确定事实。调整显示长度/换行后，复查抢先显示、侵入后句及重叠对白问题。

默认排除 OP/ED 的音频听写、歌词识别和歌词字幕校对。OP 中实际出现的作品名、原作出处、出品方/製作委员会及版权信息，以及每话话数与标题，必须作为画面字加入日语 SRT；项目另行明确要求的动画制作公司信息也应保留。以上每条画面字（含版权信息、话数和标题）用一对半角括号 `( )` 包住完整内容，多行共用一对括号。话数/标题位于 OP 前后时也按其实际出现位置纳入。按 [画面文字规范](references/subtitle-format.md#画面文字片头片尾与广告) 核对画面、排版和显示时间，不因排除 OP 音频或参考字幕缺项而漏掉。其余角色/演职员文字可在听写前用作专名证据，不要求把整份演职员表加入 SRT。先记录各集实际 OP/ED 起止时间及应纳入画面字，正片仍按完整范围处理，禁止用固定片头长度代替实际确认。只有用户明确要求纳入歌曲时才听写相应 OP/ED。

正片范围内的歌曲仍按用户要求检查；纳入歌曲时按演唱乐句打轴并保留拖音，不照搬对白裁尾规则。默认不做逐字卡拉 OK。

## 最终全文逻辑校对（必做）

完成日语 SRT 后、交付之前，读取 [最终监督校对](references/final-editorial-review.md)，由负责交付的 Agent 按原片顺序通读全部字幕，覆盖模型输出一致或自动 QC 未报警的行。这是成品的独立审校步骤，不能以模型一致、对齐分数或脚本扫描代替。长片分段阅读时保留前后文和全片术语表，记录已读字幕 ID，不能只读疑点或截断的工具输出就宣称全文检查。

听写后先按本次已保存的清单与原日语字幕核对专名，再通读整集文本逻辑，检查答非所问、否定/数字错配、关系矛盾、缺词和离谱语句。逻辑异常是回查线索，不是改写许可；提取带前后文的原音，必要时局部分离或换切窗复核。每个疑点最多三轮追加复核，不要求为凑轮数重复识别；仍听不清时，采用已对应到该句的原日语字幕措辞，记 `retained_unverified`，旧疑点继续保留。即使原句逻辑上可疑，也不凭猜测润色；明确听清且确认原字幕错误才改，并记录证据。专名字形按清单证据统一，保留实际称呼；身份或来源冲突未解决时保留原字幕写法并记 QC。没有对应原日语句的缺失块不能凭空“回退”，继续按所在分支记录缺失/推断。SRT 内不放待核标记。

修订保存原文、改文、理由、来源和涉及字幕 ID。默认 V26 全量首轮必须覆盖完整授权范围；完成后改变字词、读音、补漏或断句，重新检查受影响范围的对齐、相邻边界与覆盖即可，纯同音字形统一也须复查字符映射。只有用户明确要求保留轴的分支才比较无改时块与源时间是否一致，并记录拆分/显示间隔调整的一对多映射和声音依据。最后对实际交付版本复读改动上下文、复核全片术语一致性并运行字幕结构/时间检查，记录最终文件哈希、全量对齐覆盖与未解决项。未完成全文校对、本次模式要求的时间对齐或仍有实质疑点时不标成可直接使用。

## 验收与规模评估

依 [运行记录与验收](references/run-records.md) 完成日语 SRT、疑点复核、最终全文逻辑校对及报告，最后突出字幕成品的直接路径。中文 SRT 和日中映射仅按需生成。默认不烧录视频，用户要求预览或成片时再制作。

区分 `auto_passed`、`needs_review`、`blocked_dependency`、`failed`。前者只表示通过配置的自动检查，不代表零错误。先在当前授权内完成复核，不把常规中间步骤交给用户；有实质未解决疑点不得判通过或标成“可直接用”，只能注明具体问题及受影响时间并交付草稿。无人值守执行不等于所有片段都必须通过，也不要求用户逐分钟校对才能继续。

有独立可信日语参考时测识别错误、删除、整句遗漏和时间误差。无参考时只报告分歧、未解释语音时长、修复数量、剩余疑点及对齐失败等代理指标，不能叫真实漏句率/准确率。阈值经样本校准，不把模型自报置信度当正确率。

后续规模估算使用实测耗时、有效音频分钟、复核倍率、资源及实际 API 消耗，列明假设。各阶段落盘、按集恢复并隔离失败；实验未达标不自动扩展生产。报告明确哪些能力实际跑过、哪些缺依赖或未经验证。
