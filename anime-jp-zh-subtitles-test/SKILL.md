# 日语动画字幕生成与复核

> **TEST / 实验版 v0.8，持续迭代中。** 本流程尚未完成新组合的完整视频端到端验收，也未验证数千分钟批处理的稳定性；后续根据实际素材继续修订。

流程 v0.8（Windows／WSL 适配）。默认目标是“用户给视频，交付可直接加载使用的日语 SRT”。以 Whisper large-v3-turbo 生成日语主稿，Anime Whisper 独立听写但仅审查文本内容；确认文本并断句后，使用既有 V26 字幕对齐方法确定时间并质检，最后由负责交付的 Agent 通读成品、校对逻辑和专名，疑句回查音频。Anime Whisper 不参与断句、字幕块边界或 timing；声纹处理默认关闭，中文翻译仅在用户要求时执行。

这是供 Agent 执行的工作流技能，不是已打包的双 ASR 引擎或一键程序。执行时核实实际模型、依赖与接口；不得将技能结构验证报告为音视频试跑成功。

## 范围与运行条件

- 本机用户偏好：优先在 WSL2 Ubuntu 的 Linux 原生环境执行 ASR、音频处理和精对齐；Python、模型及计算缓存优先使用 `/home/zhaoyi/...`。Windows 可用于文件管理和结构检查，不因短测速略快而自动切换正式计算后端。WSL 不可用或关键依赖缺失时，先记录具体阻碍，再评估 Windows 后备路径；不要静默切换。稳定性优劣仍需持续运行证据，不能将此偏好报告为已验证的稳定性结论。
- 效率也是交付要求：默认保留 Turbo 主稿、Anime Whisper 文本审查、V26 对齐、全音轨查漏和最终全文校对，疑点优先局部回听/重算并复用已加载模型与缓存。声纹建库/聚类/角色比对默认跳过，不为未经验证的边际收益自动增加全片声纹集成或反复全片重跑。用户给出时限时按实际阶段耗时安排处理，扩展步骤须有明确问题和收益依据；不把短样本测速当整片含复核的总耗时，也不为赶时间把未完成的检查标成通过。
- 仅要求创建、修改或评估技能时，不启动视频听写。明确要求试跑后，完成授权范围内的听写、复核、翻译与输出，不逐步重复询问。
- 默认源语言和字幕语言均为日语。交付 UTF-8 日语 SRT，默认放在源视频同目录，命名 `<视频名>.ja.srt`；已有同名成品时保留旧版本并写明新版本路径。双路 JSON、音频片段和 QC 报告是内部处理/追溯材料，不替代用户需要的字幕成品。用户指定其他位置、格式或语言时遵从指定；不默认增加中文翻译。
- 用户明确要求给视频做字幕且未限定范围时，处理所给视频的完整时长；长视频分块落盘并支持恢复，不因旧技能名含 test 而只交付前 10 分钟。明确要求小范围实验时才按指定范围试跑；未指定实验片段时可选总计不超过 10 分钟的代表性片段并写明原片范围。不得从一个视频扩展到未指定的整个目录或其他素材。
- 原视频、原有字幕和正式技能保持可追溯。每次新建运行目录；先读 [运行记录与验收](references/run-records.md)，建立媒体、时间映射、模型与阶段记录。
- 提取音频时保留原视频时间映射，处理音轨偏移、重采样及非连续测试片段。裁剪片段的 0 秒不能误当原片 0 秒。
- ASR-A 主路固定为 Whisper large-v3-turbo，优先复用已下载的 `mobiuslabsgmbh/faster-whisper-large-v3-turbo` CTranslate2 副本；ASR-B 内容审查使用 `litagin/anime-whisper`（本机副本 `/home/zhaoyi/models/anime-whisper`，revision `22e2008a8182b357da3922a6308d095008f72973`）。两路独立解码，但同属 Whisper 系，可能共同出错；不将其描述为不同模型体系或统计独立验证。Qwen3-ASR 不再是默认依赖；需要其他体系处理剩余疑点时另按当次授权选择。
- 主路提供初稿和粗定位，不代表主路文字必然正确。Anime Whisper 仅提供漏字、错字、漏句及文本分歧候选；其标点、长句、窗口边界和任何时间输出均不得决定字幕如何断句或放置时间。其窗口信息只用于找回审查音频与匹配候选。
- 优先复用本机可用环境，先做依赖/加载检查。Turbo 检查实际 `model.bin`、配置和本地分词器；Anime Whisper 检查配置、处理器和真实 `model.safetensors`，只加载处理器不算成功。检查云同步占位和 Windows 无法读取的 WSL 符号链接，记录仓库、revision、运行库、设备与精度。任一路缺失或权重不可读时不静默换型号，双路阶段记 `blocked_dependency`。大模型及计算缓存优先放在非同步本地目录（本次可用 `/home/zhaoyi/.cache/anime-subtitle-test/`）。下载等操作遵循当次任务授权及工具权限。

先读 [本机环境与依赖](references/local-runtime.md)，可运行 `scripts/preflight.py` 做无媒体、无网络的文件和包元数据检查；该检查不加载模型，不证明 CUDA 推理可用。实际试跑前仍需记录两路真实权重加载、设备和接口检查。Qwen3-ASR 缺失不阻塞当前组合；仅修改技能不启动下载或媒体处理。

## 主路听写与独立文本审查

两路独立听完整测试范围，输出日语，不互相读取转写答案。可共享确认过的人名词表，不共享猜测台词。保存原始输出、原始置信度及片段时间；无词级时间时保留音频窗口时间，标 `chunk_only`，需要时接对齐器，不伪造精确时间或统一置信度。

ASR-A 通过本地 `faster_whisper.WhisperModel` 运行 Turbo，显式指定日语听写，保存原始 segments；需要粗词级定位时设置 `word_timestamps=True`，仍不把其词边界直接当作最终字幕 timing。遍历完返回的 segments 生成器才算该次听写完成。首轮可用 `condition_on_previous_text=False` 降低前文错误传播，实际 beam、VAD 和其他参数写入记录；测速参数不自动当成字幕质量配置。输入本地完整模型路径，避免模型别名触发隐式下载。

ASR-B 用 Transformers 的 Anime Whisper 独立听写，不先读取主稿。禁止传 initial prompt、前文转写或未核实词表提示；该模型的标点规范常省略句末「。」，所以不能据其标点或生成块来断字幕。只将文字作为审查候选，与主稿按原音范围进行一对多/多对一内容比较。保留未经提示的首轮原始输出；乱码、异常循环、触及生成上限或疑似截断均进入疑点表，不能直接送去强制对齐。重复抑制只作为单独复核试验，不覆盖首轮。两路一致也不能代替声音核对。

使用带上下文重叠的切片，两路尽量采用不同边界。可从约 20–30 秒窗口、1–2 秒重叠开始，按模型限制和场景调整，记录参数。按时间与文字共同去重，保留真实重复台词；检查首尾覆盖、切片接缝漏字及重复输出。

确认后的主稿才进入断句：结合日语语义、原音停顿及已核实的说话人交接拆为可读字幕块。Turbo segment 也只是粗定位，不能机械一段一条；Anime Whisper 的标点、块长和时间一律不参与。不得将 30 秒识别窗口直接当字幕块，或先按固定字数硬切再按字数分配 timing。无可靠句内时间时保留粗定位块，交由 V26 对齐字符，再映射回已确认的断句；相关说明见 [对齐适配约束](references/alignment-adapter.md)。

不要用一套 VAD 结果作为两路共同的硬裁剪入口。至少一路覆盖 VAD 未判为语音的原始音频时间。保留原音轨；BGM/SFX 干扰明显时可使用已安装的 vocal-separation-ensemble 技能生成人声辅助轨，仍与原音比较，防止分离损伤造成共同漏听。

## 全音轨查漏与联合复核

检查对象包含全部音频时间和字幕内部，不只遍历已有字幕行。

1. 独立 VAD 扫描整个测试音轨，必要时比较原音与辅助人声检测。VAD、能量和音频事件分类只是候选证据，不能单独证明有/无对白。
2. 对比 ASR 及字/词对齐覆盖，寻找未解释的说话区间。长字幕框覆盖整段声音不能证明里面的词齐全，不能只用字幕框并集衡量覆盖。
3. 优先按模型实际处理的原音窗口匹配两路片段，允许一对多、多对一，再比较内容。候选字级对齐未通过声音/粗边界检查时，不得据其派生精确缺字位置；整窗高相似度也不能清除短句、否定或姓名差异，保留编辑片段。汉字/假名、标点、分句差异可仅为比较做规范化，原始文本保留。否定、数字、人名、主体和短应答差异不能因大意相近而忽略。
4. 建立疑点：少句/少词、两路分歧、边界吞句、异常重复、语音无字、文字无声音、字音不匹配、异常语速、重叠对白。短声音可能是「え」「うん」，不能统一过滤。
5. 两路空白且 VAD 阴性的区间也保留记录，用偏移切窗复扫或独立音频事件检测扩大检查，不能据共同空白宣称绝无对白。抽查只是附加检查，不算全量查漏。

对疑点提取带前后文的原音频。先扩大/移动切窗重听，再按问题选辅助人声、另一模型或真正具有音频输入能力的复核模型。第三方先独立听写，再看候选，减少答案诱导。

依据声音、候选差异和对齐证据，同时决定补句、改字或改时，保存理由及来源。两票对一票不是充分依据。检测词表提示被直接复读、异常循环和模板化输出，将它们作为待查候选；未经声音支持的候选不得进入字幕。不能把增益处理或更大模型默认当作更正确。纯文字 Agent 不能声称听过音频，也不能按剧情补台词。

每个疑点默认最多 3 轮追加复核，记录方法与结果，避免原样无限重试。仍不能判断时记 `unresolved`，保留片段与候选，继续其他片段；不得悄悄删句、猜写或判通过。关键依赖/服务整体失效时停止受影响阶段。

每次修改后重查相邻边界、覆盖与证据。可只重算受影响范围及上下文；缓存键须含音频、模型/参数、文本版本。日语修订后使相关中文译文失效并重译。

## 角色声纹辅助交接边界（可选，默认关闭）

当前只生成日语 SRT 时跳过本阶段，不检查/加载声纹模型、不建角色库、不做匿名声纹聚类，也不默认执行 CAM++／ECAPA512／ResNet34 集成。断句参考语义、原音停顿及能确认的对话交接，timing 继续使用 V26；听出换人或保留重叠对白不要求先知道角色身份。声纹资源缺失、未建库或本阶段跳过不阻塞字幕，也不能单独导致 needs_review。

仅当用户另行要求角色标注/身份一致性，或明确启用声纹实验时，读取 [声纹与说话人交接点](references/voice-boundaries.md)。优先复用现有可靠库，针对确有身份判别需要的片段采用最小可行方案；先记录实际耗时与解决的问题，再决定是否扩大。声纹只能辅助身份/边界证据，不能替代字词对齐、解决重叠语音分离或单独确定精确字幕切点；不得从普通字幕请求自动恢复本阶段。

## 复用现有精对齐

此阶段先读 [本机环境与依赖](references/local-runtime.md) 和 [对齐适配约束](references/alignment-adapter.md)。本机可复用的 V26 实现在 `/home/zhaoyi/.openclaw/workspace/master_aligner_v26.py`，单文件接口为 `align_one(audio_path, srt_path, output_path, vad_mode="hybrid")`；其实现与这份实验流程的验收要求并不完全相同。不得把不存在的 Mac `align_single.py` 当作本机入口。

最终字幕 timing 使用既有 `subtitle-align-skill-gpu` 的 V26 方法；执行时读取该技能并遵守本流程的适配约束。输入为文本审查后确认的日语；主路提供可信粗范围，V26 字符对齐确定句内起止，再按确认的字幕块拆回。Anime Whisper 不提供时间锚点、不对字幕边界投票；内容修订影响到字词时，重新运行受影响范围的 V26 对齐，不能套用 Anime Whisper 的时间。

仅已有可信日语 SRT 的纯打轴请求可转给已安装的 `subtitle-align-skill-gpu`。本流程中的归一化、匹配元数据、全音轨覆盖复核和重叠对白保护必须另行核实或适配；不得直接运行旧自动压缩逻辑后声称达到新流程要求。

读取对齐模型的预处理配置。本机日语 wav2vec2 配置为 `do_normalize=true`；使用现有底层接口时须在适配器中正确进行零均值/单位方差归一化。不要假定 `whisperx.align` 已调用特征提取器。归一化和高匹配分仍不能证明文字正确。

初始句内时间只是分句估计时，可将连续对白合并回有粗定位的短语音块联合对齐，再按字符映射拆回字幕。记录外层时间保护和内部拆句策略，避免将估计分句边界误当真值；不能仅为提高通过数而放宽阈值。

适配时保留以下约束：

- 现有接口输入可信日语 SRT，全局按所给文字顺序对齐。确认片段可以单独传入，正确换算片段/全片时间；不能假定已有增量接口。
- 单文件入口只调用 `align_one`，不会自动做完整行级 QC。需要时显式调用 QC 并保存结果；行级 QC 仍不替代全音轨查漏。
- 保存匹配状态、回退标记和对齐元数据；`fill_unmatched_timings` 等估计不是匹配成功，成功写出 SRT 不代表验收通过。
- 不盲用现有 `auto_fix` 中“识别为空就缩到 0.5 秒”等启发式修复。空白可能是漏听，应返回联合复核。
- 中文不能送入日语对齐模型。文字对不上声音时检查听写，不靠拉长字幕框或挪到别处掩盖问题。
- 短音过滤、裁尾及消重叠主要面向对白；真实重叠对白需保留双方，必要时用 ASS 分层或说明 SRT 的表达限制，不能机械截短/删除。

## 日语字幕成品、可选翻译与歌曲

日语 SRT 是默认主交付物。复查错字/漏句、异常重复、断句、可读行长和显示时长、V26 匹配/回退，以及相邻对白的起止与角色交接。默认最多两行，按自然短语换行，不拆碎词组，不把整个识别窗口塞成一条；阅读压力过大时在有音频依据的短语边界拆条，不靠拉长时间侵入后句。确保序号、编码、正时长、媒体范围和播放器可解析；文件结构合格仍不能代替内容与时间复核。

仅当用户要求中文时，日语片段确认且有稳定 ID 后翻译，保留日中映射。按中文阅读合并/拆分时保留所有源片段及声音范围；检查漏译、否定、人物关系、数字、人名和语气。不能把声音不确定的日语润色成确定事实。调整显示长度/换行后，复查抢先显示、侵入后句及重叠对白问题。

OP/ED 单独标记，不自动当静音删除。固定歌词须核对 TV-size/完整版、重复段及本集版本；内容可以复用，时间需重新定位，不能仅按集数套固定时间。

无可靠歌词时可尝试歌声识别并保留疑点；不能将未完成歌曲悄悄移出验收范围。只有用户明确排除歌曲时才不纳入要求。按演唱乐句打轴并保留拖音，不照搬对白裁尾规则。默认不做逐字卡拉 OK。

## 最终全文逻辑校对（必做）

完成日语 SRT 后、交付之前，读取 [最终监督校对](references/final-editorial-review.md)，由负责交付的 Agent 按原片顺序通读全部字幕，覆盖两路一致且自动 QC 未报警的行。这是成品的独立审校步骤，不能以模型一致、对齐分数或脚本扫描代替。长片分段阅读时保留前后文和全片术语表，记录已读字幕 ID，不能只读疑点或截断的工具输出就宣称全文检查。

仅有成片也要建立有来源的专名表，检查人名、地名、组织和作品内术语的同音异写、前后称呼及上下文逻辑；未知汉字不猜定。逻辑异常、说话含混和重叠造成的离谱台词作为回听候选，提取带前后文的原音，通过实际可用的音频输入能力核查；无此能力时使用真实音频复核工具并明确记录，不能声称直接听过。语境只能提示疑点，改写必须有音频或对应画面文字等来源支持；保留原作口语、怪诞台词和有意含混，不为通顺而润色或补剧情。

修订保存原文、改文、理由、来源和涉及字幕 ID。改变字词、读音或断句后，重新检查并按需重跑受影响范围的 V26 对齐、相邻边界与覆盖；纯同音字形统一也须复查字符映射。最后对实际交付版本复读改动上下文、复核全片术语一致性并运行字幕结构/时间检查，记录最终文件哈希和未解决项。未完成全文校对或仍有实质疑点时不标成可直接使用。

## 验收与规模评估

依 [运行记录与验收](references/run-records.md) 完成日语 SRT、疑点复核、最终全文逻辑校对及报告，最后突出字幕成品的直接路径。中文 SRT 和日中映射仅按需生成。默认不烧录视频，用户要求预览或成片时再制作。

区分 `auto_passed`、`needs_review`、`blocked_dependency`、`failed`。前者只表示通过配置的自动检查，不代表零错误。先在当前授权内完成复核，不把常规中间步骤交给用户；有实质未解决疑点不得判通过或标成“可直接用”，只能注明具体问题及受影响时间并交付草稿。无人值守执行不等于所有片段都必须通过，也不要求用户逐分钟校对才能继续。

有独立可信日语参考时测识别错误、删除、整句遗漏和时间误差。无参考时只报告分歧、未解释语音时长、修复数量、剩余疑点及对齐失败等代理指标，不能叫真实漏句率/准确率。阈值经样本校准，不把模型自报置信度当正确率。

后续规模估算使用实测耗时、有效音频分钟、复核倍率、资源及实际 API 消耗，列明假设。各阶段落盘、按集恢复并隔离失败；实验未达标不自动扩展生产。报告明确哪些能力实际跑过、哪些缺依赖或未经验证。
